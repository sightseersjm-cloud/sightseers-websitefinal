01 Executive Summary

65
/100

Promising Foundation — Significant Conversion & Trust Gaps

The site has a rich feature set — V-Tours, multi-page booking, live streaming, and a large experience catalog — but suffers from unfinished conversion flows, missing trust signals, accessibility gaps, and several critical security issues that block it from performing at its potential. Addressing the top-10 priorities could realistically push scores above 80 within 60 days.

Sight Seers Caribbean is a single-page application built on a 46,000-line Design_Reference.html compiled to a minified public/index.html. The site covers tours, villa stays, yacht charters, school and senior trips, Greek-life experiences, V-Tours (live-streamed 360° sessions), and a gift card/shop. Navigation is JavaScript-driven with no real URL routing, which creates SEO and deep-link limitations. Backend is Vercel serverless + Vercel Blob with Stripe payments and Supabase real-time chat for V-Tours.

⚠
Several critical items — payment flow validation, live-stream uptime, admin panel security, and WCAG compliance — require live environment testing and are marked REQUIRES TESTING throughout this audit.

Top 5 Critical Findings

Critical
Admin passcode shipped in client JavaScript bundle
The constant ADMIN_CODE = process.env.ADMIN_PASSCODE || 'SightSeers2026!' in api/_lib/auth.js means any site visitor can read the admin passcode via the Vercel function bundle or via a network proxy in devtools.
Fix: Remove hardcoded fallback. Set ADMIN_PASSCODE env var in Vercel with a strong random string. Rotate passcode immediately.
Critical
Booking form office-hours copy reads "Sunday – Monday" (2 days only)
Hard-coded label on #p-booking shows "Office Hours: Sunday – Monday" — communicates the business is only reachable 2 days per week, destroying conversion confidence.
Fix: Correct to actual office hours (e.g., Monday – Friday, or Mon – Sat) in Design_Reference.html.
Critical
No URL routing — every page is the same URL
All 25+ pages live at the same path; JavaScript swaps div.page visibility. Deep links fail, browser back-button breaks, social shares cannot target specific pages, and Google indexes only the root.
Fix: Implement hash routing (#/tours) or proper History API (pushState) to give each page a unique, bookmarkable URL.
Critical
Critical env vars missing — payments and V-Tours are silently broken
V-Tours Stripe integration falls back to "Demo mode: Stripe not configured yet." VT_CONFIG.supabase.url === 'YOUR_SUPABASE_URL' blocks real-time chat. MUX_TOKEN_ID/SECRET are required for live streaming.
Fix: Add all env vars to Vercel: STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, MUX_TOKEN_ID, MUX_TOKEN_SECRET, SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, JWT_SECRET, ADMIN_PASSCODE.
Warning
No visible cancellation / refund policy or Terms of Service
Collecting deposits and payments without accessible refund/cancellation terms is a legal risk and a major conversion barrier, especially for premium bookings (villas, charters).
Fix: Add a Terms & Conditions page and link it in the footer and at every payment CTA.

05 Page-by-Page Audit

Homepage (#hero)

Warning
Hero slideshow has no alt text on images
Slideshow images carry no alt attributes — screen readers skip them or read filenames.
Fix: Add descriptive alt text to each slide image.
Warning
Hero CTA "Explore Water Escapes" is too narrow
Primary hero CTA targets only water-based activities, excluding families, seniors, cultural-tour seekers. Secondary CTA "Start Planning" is vague.
Fix: Run A/B test — "Browse All Experiences" vs audience-specific variants. Make "Start Planning" link directly to the booking form.
Good
Brand color system is consistent (navy + orange)
CSS variables --orange:#ef8731, --navy:#063a63, --dark:#18334c are used consistently across the hero and navigation.

Booking Page (#p-booking)

Critical
"Office Hours: Sunday – Monday" — severe copy error
The booking page shows only two days of availability. This signals the business is nearly closed and directly kills booking intent.
Warning
$15 deposit mentioned but not explained
There is a "$15 deposit" reference but no explanation of what it covers, whether it's refundable, or how it applies to the total price.
Fix: Add tooltip or inline explanation: "A $15 planning deposit is applied to your total. Refundable within 48 hours."
Warning
Form submits via SS.createBooking() — no visible confirmation email mentioned
Success message shows on screen but user is not told whether they'll receive an email confirmation. Trust gap for a financial transaction.
Fix: Send transactional email on booking submission. Mention email confirmation in success message.
Info
Upsell checkboxes are present but not copy-tested
The booking form includes upsell checkboxes — good practice — but upsell copy has not been tested for clarity or conversion impact.
REQUIRES TESTING: Measure upsell checkbox check rate in production.

Virtual Tours (#p-vtours)

Good
360° panorama viewer with keyboard navigation implemented
Arrow keys for look-around, +/- for zoom, tabindex, aria-label, role="application" all present after recent update.
Critical
Supabase URL is placeholder — real-time chat dead
VT_CONFIG.supabase.url === 'YOUR_SUPABASE_URL' check causes early exit; no chat messages can be sent or received in live sessions.
Fix: Add real Supabase URL and keys to Vercel env vars and to the frontend config.
Critical
Stripe is in demo mode — no V-Tour purchases can complete
Code shows toast: "Demo mode: Stripe not configured yet." when STRIPE_SECRET_KEY is absent. V-Tour revenue is entirely blocked.
Fix: Set STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET in Vercel. Register webhook endpoint in Stripe dashboard.
Warning
Explorer dashboard shows 19 sessions but none are backed by real data
Session list (Live Now / Today / This Week / Next Week) is UI-only; no API populates it dynamically. Users may click sessions and find them inactive.
Fix: Connect session list to Mux stream status API. Show only sessions with active or scheduled stream IDs.

Contact Page (#p-contact)

Warning
WhatsApp CTA number not verified in code
WhatsApp deep link uses a hardcoded phone number. If the number changes, the link silently breaks.
Fix: Centralize phone number as a single constant; add a canary test that checks the WhatsApp link responds.

Blog (#p-blog)

Warning

Blog exists as a page but has minimal or no real articles. This is the primary opportunity for organic SEO traffic on long-tail Caribbean travel terms.
Fix: Publish 4–8 destination guides as full blog posts. Each post should target a specific keyword cluster (e.g., "best beaches Jamaica", "all-inclusive yacht charter Caribbean").

About Page (#p-about)

Warning
No team photos, founder story, or credentials visible
About page exists but lacks photos of real team members, years in business, licenses, affiliations, or a compelling origin story — all primary trust signals for a travel business.
Fix: Add headshots, names, roles, a founder quote, and any industry certifications or accreditations.

07 Booking & Inquiry Operations

Good
Booking API (SS.createBooking) stores to Vercel Blob via api/_lib/db.js
Submissions are persisted server-side. Admin can retrieve them via the admin panel. Fallback success message shown if API is unavailable.
Warning
No automated booking confirmation email
No transactional email is sent to the customer after booking. Only a screen success message. This is a table-stakes expectation for travel bookings.
Fix: Add Resend or SendGrid integration. Trigger confirmation email from the POST /api/bookings handler with booking summary, next steps, and contact info.
Warning
No internal notification when a booking is submitted
If the team isn't actively checking the admin panel, bookings can sit unactioned for hours.
Fix: Add email or WhatsApp notification to the team inbox whenever a new booking is created.
Warning
No rate limiting on booking or contact API endpoints
/api/bookings and /api/contact have no visible rate limiting. Subject to spam submissions and scraping.
Fix: Add Vercel Edge rate limiting or a simple in-memory token bucket per IP.
Info
JWT 7-day expiry with no refresh token
Auth tokens expire after 7 days. Users are silently logged out with no token refresh mechanism. Acceptable for now but creates friction for return visitors.
REQUIRES TESTING: Confirm logout behavior on token expiry in production.

10 Mobile UX & Accessibility

Critical
No skip-navigation link for keyboard users
No <a href="#main-content" class="skip-link">Skip to main content</a> at page top. WCAG 2.4.1 Level A failure.
Critical
SPA routing breaks browser back button
Because nav() swaps page div visibility without updating the URL, pressing Back navigates away from the site rather than returning to the previous page.
Fix: Use history.pushState() when changing pages; listen to popstate to restore previous page.
Warning
Image alt text absent on gallery and tour images
Decorative hero and tour images do not carry alt text — WCAG 1.1.1 Level A failure and missed keyword opportunity for image SEO.
Warning
Color contrast not verified for secondary text
Brand orange on white (#ef8731 on #fff) yields contrast ratio ~2.8:1 — fails WCAG AA (4.5:1 for normal text). Affects any body text or CTAs using the orange color on white.
Fix: Use orange only on navy/dark backgrounds or for large text (≥18pt). For small text, shift to a darker orange (#b8610f, ~5:1 on white).
REQUIRES TESTING: Full contrast audit with axe DevTools across all pages.
Warning
No focus styles verified for interactive elements
CSS may suppress browser-default focus outlines on buttons and links, making keyboard navigation invisible.
REQUIRES TESTING: Tab through all pages and verify visible focus indicators on every interactive element.
Good
360° panorama viewer has keyboard controls and ARIA attributes
Arrow key navigation, tabindex, aria-label, and role="application" added in recent update. Comfort mode button in dock for motion sensitivity.
Info
Mobile nav exists but not tested on all breakpoints
REQUIRES TESTING: Test hamburger menu and all sub-navigations on iOS Safari 17, Android Chrome 125, and Samsung Internet.

11 SEO & Performance

Critical
Single-page app = single URL — all interior pages invisible to Google
Google crawls sightseerscaribbean.com/ only. Tours, stays, charters, destinations — none have indexable URLs. The site effectively has 1 page in Google's index.
Fix: Implement hash or pushState routing. Add <link rel="canonical"> per page. Submit XML sitemap with all page URLs.
Critical
No meta descriptions, title tags per page, or Open Graph tags
All pages share the root <title> and one meta description. Social shares all look identical. CTR from search is severely impacted.
Fix: Generate unique <title> and <meta name="description"> per page using the JS nav system. Add og:title, og:description, og:image per page.
Warning
No structured data (JSON-LD) for tours, events, or local business
TourPackage, Event (V-Tour sessions), LocalBusiness, and Review schema would enable rich results in Google Search — significant CTR boost for travel queries.
Fix: Add TourPackage JSON-LD on each tour page, LocalBusiness on the homepage, and Event schema for scheduled V-Tour sessions.
Warning
Design_Reference.html is ~5.7 MB — build pipeline critical for performance
The source file is enormous. html-minifier-terser compresses it for production, but images, CDN scripts, and uncompressed CSS may still inflate initial load.
REQUIRES TESTING: Run Lighthouse audit on production URL. Target LCP < 2.5s, CLS < 0.1, FID < 100ms.
Info
Vercel provides automatic CDN, HTTPS, and edge deployment
Vercel's global edge network provides TLS, HTTP/2, Brotli compression, and CDN caching by default — solid performance baseline for static assets.

12 Security, Privacy & Compliance

Critical
ADMIN_CODE hardcoded in api/_lib/auth.js
ADMIN_CODE = process.env.ADMIN_PASSCODE || 'SightSeers2026!' — the fallback is the actual admin credential. Visible in Vercel function bundles via devtools.
Fix: Remove fallback value entirely. Set ADMIN_PASSCODE env var to a randomly generated 32-char string. Rotate immediately.
Critical
JWT_SECRET falls back to BLOB_READ_WRITE_TOKEN
SECRET = process.env.JWT_SECRET || process.env.BLOB_READ_WRITE_TOKEN — if JWT_SECRET is not set, the Vercel Blob token (which grants write access to all blob storage) doubles as the JWT signing secret. Token exposure = full blob compromise.
Fix: Set a dedicated JWT_SECRET env var (min 256-bit random). Remove the BLOB_READ_WRITE_TOKEN fallback.
Warning
No CAPTCHA or bot protection on public forms
Booking form, contact form, and sign-up are unprotected against bot submissions. Spam bookings will pollute the admin panel.
Fix: Add Cloudflare Turnstile (free, privacy-respecting) to booking and contact forms.
Warning
No Content-Security-Policy header
No CSP header limits XSS attack surface. Especially important given CDN script dependencies (Three.js, HLS.js) that could be compromised.
Fix: Add CSP via Vercel headers config in vercel.json. Allowlist only required CDN origins and script hashes.
Info
Stripe webhook uses manual HMAC-SHA256 — correct but fragile
Manual webhook verification in api/stripe-webhook.js is functionally correct. However, it's missing the stripe npm package's timing-safe compare and may drift from Stripe's spec on future updates.
Fix (low priority): Consider adding the official stripe npm package and using stripe.webhooks.constructEvent() for future-proofing.
Good
Password hashing uses PBKDF2 with 210,000 iterations (strong)
PBKDF2-SHA512 at 210,000 iterations exceeds OWASP recommended minimums. 64-byte key output. Industry-standard for user passwords.
Good
JWT uses timing-safe comparison for token validation
api/_lib/auth.js uses timing-safe byte comparison for HMAC verification — protects against timing-oracle attacks.

13 Analytics

Critical
No analytics platform detected in codebase
No Google Analytics 4, Plausible, Fathom, or Vercel Analytics script found in Design_Reference.html or the API layer. No conversion events can be measured.
Fix: Add Vercel Analytics (zero-config, privacy-preserving) as a first step. Then add GA4 for full funnel tracking.
Critical
No conversion tracking on booking form, Stripe checkout, or sign-up
Without event tracking, there is no visibility into which pages drive bookings, where users drop off in the funnel, or which channels convert.
Fix: Implement GA4 + Google Tag Manager. Track: form_start, form_submit, booking_created, stripe_checkout_initiated, stripe_payment_complete, signup_complete, vtour_session_joined, vtour_purchase.
Info
V-Tours metric bars are UI placeholders (34%, 61%, 78%, 18%)
The metric tiles in the V-Tours section display hardcoded values. They are not wired to any real data source. Replace with live Mux/Stripe/Supabase data once env vars are configured.
